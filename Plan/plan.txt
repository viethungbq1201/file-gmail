# Xây dựng Web App Upload File → Gmail bằng ASP.NET Core + React

## 1. Vai trò

Bạn là Senior Full-stack Engineer, có kinh nghiệm với:

* ASP.NET Core / .NET 8+
* C#
* Gmail API
* Google OAuth 2.0
* React
* Vite
* TypeScript
* REST API
* Security
* Responsive UI/UX
* Clean Architecture ở mức phù hợp với project nhỏ

Hãy xây dựng một web application hoàn chỉnh từ thư mục project hiện tại.

Project hiện tại **chỉ mới có file OAuth Client JSON được tải từ Google Cloud**, chưa có source code nào khác.

Không được giả định rằng project đã có backend/frontend.

---

# 2. Mục tiêu sản phẩm

Xây dựng một web app có chức năng:

> Người dùng mở website → chọn một hoặc nhiều file ảnh/PDF → xem trước file → nhập thông tin email nếu cần → bấm "Gửi" → backend nhận file → gửi toàn bộ file đó đến một Gmail cố định thông qua Gmail API.

Luồng tổng quát:

```text
User
  ↓
React Web App
  ↓
ASP.NET Core Web API
  ↓
Google Gmail API
  ↓
Gmail cố định
```

Không sử dụng Zalo.

Không cần database cho MVP.

Không sử dụng SMTP.

Không sử dụng S3.

Không sử dụng Redis.

Không sử dụng RabbitMQ.

Không lưu file lâu dài trên server.

# 13. Gmail OAuth flow

Backend cần hỗ trợ OAuth 2.0.

Scope:

```text
https://www.googleapis.com/auth/gmail.send
```

Flow:

```text
GET /api/gmail/auth
        ↓
Google OAuth authorization
        ↓
User login
        ↓
Google consent
        ↓
GET /api/gmail/oauth/callback
        ↓
Exchange authorization code
        ↓
Save token
```

Sau khi có refresh token:

```text
Frontend
   ↓
POST /api/gmail/send
   ↓
GmailService
   ↓
Google Gmail API
```

Backend không yêu cầu user đăng nhập Google mỗi lần gửi.

```text

   ↓

   ↓
MIME message
   ↓
Gmail API
```


# 19. Authentication cho web app

Vì endpoint gửi email có thể bị public abuse, cần có một lớp bảo vệ đơn giản.

MVP có thể dùng:

```text
APP_ACCESS_KEY
```

Frontend có một màn hình:

```text
Nhập mã truy cập

[****************]

[ Vào ứng dụng ]
```

Backend kiểm tra access key.

Không lưu access key hard-code trong frontend.

Có thể gửi bằng header:

```http
X-App-Key: ...
```

Backend lấy giá trị đúng từ environment variable.

Nếu triển khai authentication đầy đủ thì có thể thay thế bằng JWT sau, nhưng không cần over-engineer MVP.

# 33. Gmail MIME implementation

Tạo email MIME multipart/mixed.

Ví dụ conceptual:

```text
Content-Type: multipart/mixed

--boundary
Content-Type: text/plain

Email body

--boundary
Content-Type: application/pdf
Content-Disposition: attachment; filename="document.pdf"
Content-Transfer-Encoding: base64

...

--boundary
Content-Type: image/jpeg
Content-Disposition: attachment; filename="image.jpg"
Content-Transfer-Encoding: base64

...
```

Encode thành base64url phù hợp với Gmail API.

Không tự tạo MIME implementation quá mong manh nếu Google library hỗ trợ tốt hơn.

* không giữ process/background worker lâu dài
* không phụ thuộc server luôn chạy

Nếu token cần persistent storage trên Render, phải thiết kế cách lưu secret/token phù hợp.

Không giả định filesystem của Render là persistent.

# 46. Token handling

Access token có thời hạn.

Refresh token phải được sử dụng để tự động lấy access token mới.

Không yêu cầu user authorize mỗi lần gửi.

Nếu refresh token invalid/revoked:

```text
authorized = false
```
